## 可重复运行的检查

```powershell
pwsh -File scripts/build.ps1 -Configuration Debug
pwsh -File scripts/build.ps1 -Configuration Release
pwsh -File scripts/verify-package.ps1
```

本轮打包使用本地缓存，并为该构建进程设置 NuGetAudit=false；网络无法访问漏洞数据源，不能声称完成在线依赖漏洞审计。该设置未写入项目默认配置。

管理员集成测试在提升权限的 PowerShell 中运行，会拒绝覆盖现有安装或配置：

```powershell
pwsh -File scripts/test-admin.ps1 -InstallDirectory D:/TouchLock-Validation
```

可用 -UninstallOnly 复核卸载，-AuthenticationOnly 跳过故障注入。交互桌面可追加 -VerifySettingsUi，验证开启前蓝牙/设备页可访问、开启后受限且显示页可用、取消保护后恢复。测试会打开和关闭系统设置窗口，不改变蓝牙硬件或配对。UI 超时须报告失败，不能改成成功。

## 希沃验收步骤

1. 临时解冻系统盘，准备物理键鼠，把程序安装到非冻结 NTFS 盘。开启自启动后确认勾选与实际服务配置一致。
2. 操作前保存只读清单：运行安装目录中的 TouchLock.exe --inventory 并重定向到文件。在关于页确认日志实际目录。
3. 确认识别全部五个 Kuma 实例。锁定后核对五个设备均禁用、触摸点击/拖动/滑动均停止，同时物理键鼠、触控板正常。
4. 错误口令或取消应保持锁定。再次按 Ctrl+Win+Alt+Enter 应请求管理口令；正确口令恢复全部接管实例并核对实际触摸。
5. 验证蓝牙与已连接设备页面、ms-settings:bluetooth、ms-settings:connecteddevices 入口受限。错误/取消口令不解除保护，正确口令解除；已有蓝牙键鼠不断连，显示等其他设置页可用。
6. 在 200% 系统缩放下检查安装、关于和密码窗口；拉伸到最小尺寸，确认文本可读、内容可滚动、按钮可操作。
7. 正常退出后重开、服务重启和 Windows 重启均恢复运行默认值；托盘被结束后自动拉起仍保持当前保护。口令及自启动设置保留。
8. 在解冻状态完成一次重启，再冻结并重新启动，确认程序、口令、日志位置与自启动均正确。锁屏/睡眠/触摸设备变化按既有应急恢复策略结束本次锁定。

## 失败时提供

提供关于页所示 Logs 目录的完整日志、操作前后 inventory 清单、Windows 版本与版本类型、TouchLock 构建提交号、操作时间与顺序，以及设备管理器操作前后状态。不要提供 password.json、口令、Hash 或 Salt。不要删除未完成的 recovery.json 或蓝牙策略恢复记录；先保留用于恢复和排查。
